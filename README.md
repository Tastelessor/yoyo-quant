# yoyo-quant

量化交易学习与系统开发仓库。

## 核心方向

**专注领域：波动率数据分析 + A股量化**

不做"看指标猜涨跌"的散户游戏。目标是建立可回测、可迭代的系统化策略框架。

## 铁律

全局硬约束，无例外。所有设计、编码、测试决策必须遵守：

1. **模块解耦**：每个模块有明确的数据结构契约和单向数据流。改一个模块绝不导致其他模块崩溃。模块间通过接口（而非实现细节）交互。
2. **绝对TDD**：先写测试，再写实现。没有测试覆盖的功能不算完成。测试先于代码，测试即文档。
3. **技术栈先行**：动手前明确每个模块用什么库、什么版本、什么接口。不允许"先跑起来再说"——先定义契约，再填实现。

## 做什么

- **波动率数据分析**：利用期权历史/隐含波动率数据辅助股票交易决策（IV均值回归、IV skew分析、PCR等），不做期权实盘
- **A股量化**：事件驱动、配对交易、可转债策略
- **数据基础设施**：行情数据获取、清洗、存储的自动化管道
- **策略回测**：基于rqalpha快速验证策略的正期望性，同时理解引擎内部逻辑以识别回测陷阱

## 不做什么

- **不依赖大众指标做alpha**：MACD、Bollinger Bands、RSI这类指标已经过度使用，无法提供超额收益。它们可以作为辅助过滤器，但不是信号来源
- **不做"AI自动交易"**：AI可以辅助代码生成和数据处理，但回测验证和风险管理必须由人来审查。用AI做回测 = 引入过拟合和前视偏差
- **不重复过去的失败**：多因子模型、动量策略、AI多Agents组合——这些都试过，效果差。不换皮重做
- **不做高频**：设备和数据都不支持，不碰
- **不做期权实盘**：期权仅作为数据分析工具辅助A股决策，不涉及期权开户或策略执行

## 阶段规划

### Phase 1: 基础建设（第1-6周）

- **Week 1-2**：Python向量化练习（numpy/pandas），环境搭建（tushare/akshare/rqalpha），确定各模块的数据结构契约（DataFrame schema），跑通第一个rqalpha回测
- **Week 3-4**：建立数据获取和存储的基本流程，实现第一个均值回归策略的回测（TDD：先写测试再写代码）
- **Week 5-6**：理解rqalpha内部逻辑（撮合、复权、停牌处理），处理遇到的A股边界情况，为每个模块补充测试用例

### Phase 2: 框架设计（第2-3月）

- 模块化策略框架：数据层 → 信号层 → 执行层 → 回测层
- 数据与可视化层解耦：核心逻辑产出DataFrame，可视化层独立
- A股规则适配（T+1、涨跌停、停牌处理等）
- 波动率数据分析基础（IV/HV计算、波动率锥构建）

### Phase 3: 策略开发（第3月+）

- 具体策略实现和回测验证（逐笔审计，验证决策逻辑正确性）
- 波动率数据分析应用（IV均值回归信号、PCR情绪指标等）
- 机器学习辅助因子挖掘（探索性，非核心）
- 风控体系设计

## 技术栈（规划中）

- Python 3.11+
- 数据源：tushare / akshare
- 回测：rqalpha（用它快速跑通策略，遇到限制时深入源码理解并按需定制）
- 数据处理：pandas / numpy
- 可视化：matplotlib（静态验证）→ plotly（交互式探索），数据层与展示层解耦

## 回测策略

**核心原则：用别人验证过的轮子跑起来，但自己清楚轮子怎么转的。**

- **阶段1**：使用rqalpha快速验证策略的正期望性，避免从零造引擎消耗精力
- **深入理解**：遇到边界情况（跌停、复权、停牌）时，阅读rqalpha源码理解其处理方式
- **按需定制**：当rqalpha限制策略设计时，基于对引擎的理解自建轻量回测逻辑
- **审计追踪**：每个决策点必须可追溯——信号值、触发条件、逐笔成交记录、中间变量

**数据流**：
```
                ┌→ backtest（模拟评估）
data → factors → strategies → portfolio → risk ─┤

                                            visualization
```

## 快速开始

1. 克隆仓库
2. `python3 -m venv .venv && source .venv/bin/activate`
3. `pip install -e ".[dev]"`
4. `pytest` — 跑通所有测试
5. 开发规范和模块契约见 CLAUDE.md
